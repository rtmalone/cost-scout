# cost-scout Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pnpm ui` starts a local page where a reviewer asks cost-scout a question, watches each turn and tool call on a timing chart, and reads findings as they arrive.

**Architecture:** Two small hooks on `runAgent` report when each model request starts and ends. A plain `node:http` server runs one agent session at a time and streams its events to the browser as newline-delimited JSON on the response to `POST /api/run`; closing that request aborts the run. A React + Vite page folds the events into state with a pure reducer and renders the two-pane "Waterfall" layout.

**Tech Stack:** TypeScript, Node `node:http`, `tsx`, `node:test`, React 19, Vite, `@fontsource/manrope`, `@fontsource/jetbrains-mono`.

**Spec:** `docs/superpowers/specs/2026-10-20-web-ui-design.md`. Read it before any UI task: copy, layout and colours come from it.

## Global Constraints

- The CLI (`pnpm scout`) and evals (`pnpm eval`) behave exactly as before. Same prompt, tools, limits, model selection (`COST_SCOUT_MODEL`, default `claude-sonnet-5-5`).
- The agent loop stays non-streaming.
- Server binds `127.0.0.1` only. `ANTHROPIC_API_KEY` never leaves the server process.
- One run at a time per server.
- The UI never offers an apply/fix action.
- Everything the model wrote (titles, evidence, SQL, summary) renders as plain text: no `dangerouslySetInnerHTML`, no Markdown-to-HTML. The data the model reads is untrusted.
- Palette, fonts and copy exactly as in the spec's tables and bullets (Nord light; thinking `#88C0D0`, queries `#D08770`, findings `#A3BE8C`, errors `#BF616A`, axis `#4C566A`).
- Imports use `.ts`/`.tsx` extensions, matching the repo (`allowImportingTsExtensions`).
- Tests run with `pnpm test` (`node --import tsx --test test/*.test.ts`), no network, no API key; the agent is driven by the fake client pattern in `test/agent.test.ts`.

## Review Focus

1. **The reviewer closes or reloads the tab mid-run.** The server must abort the run so it stops spending tokens. Test in Task 3.
2. **A second tab clicks Investigate while a run is going.** It gets a clear "a run is already in progress" error, not a second paid run. Test in Task 3.
3. **No dataset or no API key.** The page says exactly what to run (`pnpm generate`, or add the key to `.env`) and Investigate is disabled. Tests in Task 3 (status) and Task 4 (reducer).
4. **A long run (up to 25 turns, a few minutes).** The axis ticks stay readable at any length. Test in Task 4.
5. **The run ends abnormally** (API error, turn cap, stopped by the user). The status line says how it ended, and the findings so far stay visible. Tests in Task 4.

### Task 3: Local HTTP server and `pnpm ui`

**Files:**

- Create: `src/ui/server.ts` (the testable server), `src/ui/main.ts` (entry: env, dataset check, listen)
- Modify: `package.json` (scripts)
- Test: `test/ui-server.test.ts`

**Interfaces:**

- Consumes: `runSession`, `monthlySpend`, `RunEvent`, `UiStatus` (Task 2).
- Produces:
  ```ts
  export interface UiServerOptions {
    db: ReadOnlyDb | null;
    problems: string[];
    model: string;
    staticDir: string;
    client?: MessagesClient;
    maxTurns?: number;
  }
  export function createUiServer(opts: UiServerOptions): http.Server;
  ```
  HTTP API:
  - `GET /api/status` → `200` JSON `UiStatus`. `ready` is `problems.length === 0`; `busy` is true while a run is going.
  - `POST /api/run`, body `{"question": string}` → `200`, `Content-Type: application/x-ndjson`, one `RunEvent` JSON per line, ended when the session ends. `503` JSON `{error}` when not ready (error = problems joined with a space); `409` JSON `{error: 'A run is already in progress.'}` when busy; `400` for a body that isn't JSON with a string `question` (an empty string is fine).
  - If the client closes the request before the run ends, abort the run's `AbortController`.
  - Any other `GET` serves files from `staticDir` (`/` → `index.html`). Paths resolving outside `staticDir` → `404`. If `index.html` is missing → `500` text `The page isn't built. Run pnpm ui.`
- `main.ts` problems (exact copy): `No dataset found. Run pnpm generate first.` when the DuckDB file is missing; `ANTHROPIC_API_KEY is not set. Copy .env.example to .env and add your key.` when the key is missing. Loads `dotenv/config` like `src/cli.ts`. Port from `COST_SCOUT_UI_PORT`, default `4317`. Listens on `127.0.0.1` and prints `cost-scout UI: http://127.0.0.1:4317`. `staticDir` is `web/dist` at the repo root.
- `package.json` scripts: `"ui": "vite build web && tsx src/ui/main.ts"`, `"ui:dev": "vite web"` (dev proxy set up in Task 4).

- Produces (all pure, no DOM):
  ```ts
  // format.ts
  export function usd(n: number): string; // 1255.5 → "$1,256"; 40 → "$40"
  export function shortenId(id: string, max = 22): string; // middle ellipsis "…" when longer than max, keeps both ends
  export function axisTicks(totalMs: number): number[]; // seconds from 0 to the last multiple of step ≤ total, using the smallest step in [5,10,15,30,60,120,300] that gives ≤ 7 ticks
  // labels.ts
  export type CallKind = "query" | "finding" | "error";
  export function callLabel(call: ToolCallRecord): {
    kind: CallKind;
    label: string;
    result: string;
  };
  // runState.ts
  export interface CallView {
    id: string;
    kind: CallKind;
    label: string;
    result: string;
    sql?: string;
    durationMs: number;
  }
  export interface TurnView {
    turn: number;
    startMs: number;
    durationMs?: number;
    text: string;
    calls: CallView[];
  }
  export interface RunState {
    phase: "idle" | "running" | "finished";
    question: string;
    startedAtMs: number;
    monthlySpendUsd: number;
    turns: TurnView[];
    findings: Finding[];
    savingsUsd: number;
    end?: {
      stopReason: StopReason;
      stopDetail?: string;
      summary: string;
      turns: number;
      toolCalls: number;
      usage: Usage;
    };
    error?: string;
  }
  export type ClientEvent =
    | { type: "client_started"; question: string }
    | { type: "client_error"; error: string };
  export const initialState: RunState;
  export function reduce(state: RunState, e: RunEvent | ClientEvent): RunState;
  export function statusText(state: RunState, status: UiStatus | null): string;
  // stream.ts
  export function readNdjson(
    body: ReadableStream<Uint8Array>,
    onEvent: (e: RunEvent) => void,
  ): Promise<void>;
  ```
- `callLabel` rules (copy from the spec): `run_sql` → label is `input.purpose`, else the SQL with whitespace collapsed, cut to 60 chars with `…`; result is `summary`. `describe_schema` → `Read the schema`; result `3 tables`, from the leading number in `summary`. `report_finding` → `Reported: <title>`, result `usd(savings) + '/mo'`, kind `finding`. Any `isError` call → kind `error`, label as above (`report_finding` errors read `Finding rejected: <title>`), result is the summary.
- `reduce` rules: `turn_started` appends a turn (`startMs` relative to the run start); `turn_ended` sets `durationMs`/`text`; `tool_call` adds a `CallView` to its `call.turn`; `finding` appends and adds to `savingsUsd`; `run_finished` sets `end` and `phase:'finished'`, gives any turn without `durationMs` one equal to now minus its start, and clears the last turn's `text` when it has no calls and the text equals the summary (the summary shows in the results pane instead); `run_failed`/`client_error` set `error` and `phase:'finished'`; `client_started` resets to `initialState` with `phase:'running'` and the question.
- `statusText` (exact copy): not ready → the first problem; idle → `Ready when you are`; running, last turn open → turn 1 `Reading the question`, later turns `Thinking about what to check next`; running, last turn closed → `Running queries`; finished `completed` → `Finished · {N findings}`; `aborted` → `Stopped by you · {N findings} so far`; `max_turns`/`token_budget`/`max_tokens`/`refusal`/`context_window_exceeded`/`api_error`/`unexpected_stop_reason` → `Stopped early: <stopDetail> · {N findings} so far`. `{N findings}` is `1 finding`, `0 findings`, `2 findings`; `error` → `Something went wrong: <error>`.
- `vite.config.ts`: root `web`, React plugin, `build.outDir` `dist`, dev server proxy `/api` → `http://127.0.0.1:4317`. `web/tsconfig.json`: `jsx: react-jsx`, `moduleResolution: bundler`, `allowImportingTsExtensions`, `noEmit`, `strict`, `types: ["vite/client", "node"]` (the event types reach `src/agent/run.ts`), include `src` and `../src/ui/events.ts`.
- Deps: `react`, `react-dom`, `@fontsource/manrope`, `@fontsource/jetbrains-mono`; dev: `vite`, `@vitejs/plugin-react`, `@types/react`, `@types/react-dom`.
